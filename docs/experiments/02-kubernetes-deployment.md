# EXP-002: Trusted Kubernetes deployment and GitOps lifecycle

**Status:** Executed on a 3-node homelab cluster (2026-11-15/16). Scenarios A–G and the hook lifecycle (H) are
complete. **Not run:** Codex runtime (no credentials; [#10](https://github.com/jlaska/herdrnetes/issues/10)) and a real
node drain (needs owner approval; replaced by a GitOps node relocation). Proposed for review; no ADR changes made.
Tracking issue: [#3](https://github.com/jlaska/herdrnetes/issues/3). Builds on
[EXP-001](01-session-recovery.md) (FIND-001–012).

Evidence types used below: **[observed]** = measured in a run here, **[EXP-001]** = carried over from the local
experiment, **[inference]** = our reasoning, not yet tested. Per-run measurements: [`experiments/exp-002/RESULTS.md`](../../experiments/exp-002/RESULTS.md).
Harness, image and manifests: [`experiments/exp-002/`](../../experiments/exp-002/). Raw evidence (screens,
`session.json`, logs, backups) stays private because it contains conversation text and session IDs. Cluster, node and
GitOps-repository names are withheld.

## Hypotheses and outcome

| Hypothesis | Outcome |
| --- | --- |
| One trusted Herdr can run headless as a pod under Pod Security `restricted`, with a read-only root filesystem and no ServiceAccount token. | **Confirmed** (FIND-013). |
| Herdr session state, agent conversations and repository changes survive pod replacement on separate home and workspace PVCs (REQ-003). | **Confirmed** for every graceful replacement. Forced exits lose up to 5 s of layout changes, as in EXP-001 (FIND-014, FIND-015). |
| A Herdr-only GitOps image change keeps sessions and agent conversations (primary acceptance). | **Confirmed** for 0.9.4 → 0.9.5, 0.9.5 → 0.9.4, and 0.9.5 → 0.8.0 → 0.9.5. Pane processes are interrupted, as ADR-0001 accepts (FIND-015). |
| An agent-only change keeps conversations. | **Confirmed** for Claude Code 2.1.311 ↔ 2.1.325 (one round trip). Codex untested (#10). |
| Rollback is safe with a state backup. | **Confirmed** across the tested range. Hooks must be reconciled to the running Herdr version (FIND-017). |
| Kubernetes readiness implies recovered sessions. | **Not assumed and measured separately.** Readiness came within about 1 s of restore in every run. A missing saved directory still gave Ready with panes in `restore_error` (FIND-021). |
| Config changes are applied predictably. | **Partly:** a ConfigMap change does not restart the pod and is not picked up until `reload-config` or the next restart (FIND-020). |

## 3. Test procedures

Scripts, run from a workstation (`CTX=<kube context>`, `EXP_EVIDENCE=<private dir>`):

```bash
H=experiments/exp-002/harness
bash $H/scenario.sh setup r1 && bash $H/scenario.sh agent r1      # A: 2 repos, 2 workspaces, 5 panes, Claude + codeword
bash $H/scenario.sh disrupt r1 delete|grace1|force|kill|oom      # B, C1–C6: disruption + recovery measurement + probe
bash $H/scenario.sh ask r1 <label>                               # codeword recall by the resumed agent
GITOPS_DIR=… GITOPS_FILE=…/statefulset.yaml APP=… bash $H/gitops-step.sh prepare|apply r1 <variant|node=NAME|node=-> <label>  # D, E, G3/G4
GITOPS_DIR=… GITOPS_CONFIG=…/config.toml APP=… bash $H/config-step.sh prepare|apply r1 true|false <label>                     # F
uv run --script experiments/exp-001/compare.py diff $EXP_EVIDENCE/r1/baseline-agent $EXP_EVIDENCE/r1/after-<label>
```

Recovery is measured separately from readiness. The run used these controller-polled signals:
- `server_answers_s`: `herdr status server` responds.
- `layout_restored_s`: `herdr api snapshot` shows **at least** the baseline counts (2 workspaces, 5 panes). Counts only.
- `agent_detected_s`: a pane in `herdr api snapshot` has `agent: "claude"`. This field agreed with the
  `snapshot.agents` collection in all 20 saved snapshots (Herdr 0.8.0, 0.9.4, 0.9.5). It was always present in the
  same poll as the layout, so it reflects Herdr's restored session state, **not** a running or resumed Claude.

In review these were found too weak to support identity or resume claims. Two checks fill the gap:
- **Probes.** Each `after-*` probe records every pane's label, cwd and foreground process, plus git status and history.
  Its identity was re-checked offline with `harness/recovery.py audit` (results in
  [RESULTS.md](../../experiments/exp-002/RESULTS.md#recovery-identity-re-check-offline)).
- **Codeword.** Only the codeword answer shows the conversation itself resumed. It was asked after each probe and was
  **not timed**.

The harness now measures `layout_identity_s` (labels, positions, cwds), `agent_metadata_s` (same agent and session
reference at the same pane), `agent_process_s` (that pane's foreground process is `claude` again) and `restore_errors`
against a snapshot taken just before each disruption. Those metrics postdate the published run.

Then a probe diffs pane cwds, foreground processes, git status and history against the baseline. Finally the agent is
asked for a codeword it was given before any disruption. Every GitOps step first backs up the state (a tarball to the
controller plus a `session.json` copy on the PVC).

Local pre-cluster tests: `image/smoke.sh` (s1) and `image/hooks-test.sh` (h-R, h-S) ran under podman with the same
pod constraints.

## 5. Findings

- **FIND-013 — Herdr runs as a locked-down headless pod, and agents work without interactive login.** [observed]
  - **Isolation:** `tini` → `herdr server` as uid 1000 ran under PSA `restricted`, with a read-only root filesystem, no
    capabilities, `RuntimeDefault` seccomp, no ServiceAccount token, deny-ingress NetworkPolicy, and no service-link
    or `KUBERNETES_*` variables.
  - **Environment:** the entrypoint starts the server with `env -i` and an allowlist, so panes see only that (FIND-011
    mitigation).
  - **Paths:** `HERDR_CONFIG_PATH` on a read-only ConfigMap and the session directory on the home PVC work as FIND-005
    predicted.
  - **Headless:** no client was ever attached. The server creates no default workspace when headless; EXP-001 saw one
    with a TUI client.
  - **Claude Code:** started with `CLAUDE_CODE_OAUTH_TOKEN` from a SealedSecret and a seeded `hasCompletedOnboarding`,
    with no login or onboarding screen. The per-folder trust dialog still needs a human answer once per repository
    path (FIND-012).
  - → REQ-002, REQ-004.
- **FIND-014 — Recovery time is dominated by Kubernetes, not Herdr.** [observed]
  - **Herdr's own time:** the SIGTERM save took 0.18–0.22 s on Longhorn in every graceful run, including a 1 s grace
    period. From the restore to Herdr detecting the relaunched Claude took 1.9 s (B, Herdr log). Conversation resume was
    confirmed by codeword recall but not timed, so no resume latency is claimed.
  - **Kubernetes's time:**
    - Pod replacement: 10 s on the same node with a cached image.
    - First image pull: about 12 s.
    - Cross-node Longhorn detach and attach: 17 s.
    - Kubelet crash backoff: 10 s or more on repeated in-container crashes (C1: 2.5 s, then 14.6 s).
  - **Grace period:** the 60 s grace is ample at this scale: one idle agent, 5 panes, 2.6 KB of `session.json`. Shutdown
    with busy agents and large sessions was not measured.
  - **Readiness:** readiness came within about 1 s of restore and is a reasonable *server* signal. It is not a session
    signal (FIND-021).
  - → REQ-006.
- **FIND-015 — GitOps image upgrades and rollbacks preserve sessions and agent conversations; they interrupt
  processes.** [observed] This is the primary acceptance criterion.
  - **Steps:** six Argo CD-driven image changes, D1–D3 and E1–E3:
    - Herdr 0.9.5 → 0.9.4 → 0.9.5 → 0.8.0 → 0.9.5 with Claude fixed.
    - Claude 2.1.311 → 2.1.325 → 2.1.311 with Herdr fixed.
  - **Each step preserved:**
    - Herdr saved on SIGTERM.
    - The new version restored the session (`outcome=ok`, `session.json` schema `version: 3` throughout).
    - Every pane cwd, git trees and shell history.
    - The Claude conversation: `claude --resume <id>` recalled the codeword.
  - **Each step lost:** the same as any pod replacement — pane processes, in-flight turns, exported env and launch
    flags (FIND-002, FIND-008).
  - **0.8.0 differences:** its first `agent prompt` returned `agent_prompt_stalled` once, and its status vocabulary
    differs (`idle` where 0.9.5 shows `done`).
  - → REQ-002, REQ-003, REQ-006; REQ-009 not met (expected).
- **FIND-016 — Argo CD repository polling, not Kubernetes or Herdr, dominates GitOps change latency.** [observed]
  - **Push → Synced:** 10–11 s in eight steps; 247 s (E3) and 327 s (E1) in the other two. Argo's own apply then took
    about 1 s.
  - **Variance:** the spread is consistent with periodic polling and no webhook.
  - **Signed commits:** the owner-signed policy adds a hardware-key touch per change. Automation that pushes to the
    same branch (Renovate pushed 7 commits during this run) can reject a just-signed commit as non-fast-forward. The
    harness now fast-forwards immediately before committing.
  - → REQ-002.
- **FIND-017 — Reconciling integration hooks on every start keeps them matched to the Herdr binary in both
  directions; without it a rollback leaves an undetectable mismatch.** [observed]
  - **Strategy R:** the entrypoint runs `herdr integration install claude|codex` on each start.
    - Hooks went to v11/v10 (0.9.5), v10/v9 (0.9.4) and v7/v7 (0.8.0), in the cluster as well as locally (h-R).
    - User-owned Claude hooks and permissions survived every hop.
    - `settings.json` was byte-identical after a full round trip.
    - 0.9.5 removed the deprecated Codex turn hooks that 0.9.4 installs.
  - **Strategy S** (install once and keep):
    - It left 0.9.5's v11 hook under 0.8.0.
    - 0.8.0's `integration status` reported it as `current (v11)`, so a startup check based on `status` cannot detect
      the mismatch.
    - EXP-001 showed the runtime cost: degraded agent status.
  - **Recommendation:** strategy R. It is idempotent, preserves user settings, supports rollback, and is cheap (about
    0.1 s). It can be turned off with `HERDRNETES_HOOKS=skip`.
  - → REQ-003, REQ-006.
- **FIND-018 — An out-of-memory pane takes down the whole Herdr pod.** [observed]
  - **What happened:** a process in one pane allocated past the 4 Gi container limit. The container was `OOMKilled`
    (exit 137) with no Herdr shutdown save.
  - **Impact:** every pane and agent process ended. Herdr restored from the last autosave, 18 s old.
  - **Why** [inference, the selected victim was not checked]: this is consistent with Kubernetes on cgroup v2 setting
    `memory.oom.group` for the container.
  - **Limits:** Kubernetes cannot bound a single pane inside one container. In the trusted single-pod model, one
    runaway build or agent tool call interrupts everything.
  - → REQ-009, REQ-011, ADR-0001 consequence ("shared trusted execution is not a security boundary") — also not a
    *resource* boundary.
- **FIND-019 — Force deletion can briefly overlap two Herdr writers on one node; across nodes, Longhorn RWO prevents
  it.** [observed]
  - **Same node:** `kubectl delete --force --grace-period=0` still delivered SIGTERM, and Herdr saved in 0.2 s. The
    replacement pod was created 0.17 s after the delete, before the old process exited. Both pods could mount the RWO
    volume on that node. No corruption occurred: the old server exited first, but nothing guarantees that ordering.
  - **Across nodes** (G3): the new pod's attach waited (`FailedAttachVolume … already exclusively attached`) until
    the old node detached.
  - **Herdr's own check:** Herdr has no single-writer lock on `session.json` [inference, from EXP-001 source reading
    of atomic rename without a lock].
  - → REQ-006.
- **FIND-020 — ConfigMap changes neither restart the pod nor reach the running server until `reload-config`.**
  [observed]
  - **Propagation:** with a fixed-name ConfigMap and no reloader, a GitOps config change appeared in the mounted
    file 7–75 s after Argo CD applied it (atomic `..data` swap).
  - **Herdr's reaction:** none. It logged nothing and changed nothing in the next 30 s. `herdr server reload-config`
    then reported `applied` with no diagnostics.
  - **Restarts:** the pod, server PID and restart count were unchanged, so panes and agents were not interrupted.
  - **Consequence:** the declared config and the running config can silently differ until an explicit reload or the
    next pod start.
  - **Not verified:** whether `pane_history` itself takes effect live.
  - → REQ-002.
- **FIND-021 — A missing saved directory is preserved, not re-rooted; a rename under a running Herdr is persisted
  silently.** [observed]
  - **Missing at start** (G2b: renamed, then SIGKILL so no save):
    - Herdr logged `WARN preserving unavailable restored pane cwd` and kept each affected pane with
      `restore_error: "Saved directory is unavailable…"`.
    - It started no shell or agent there and did not rewrite `session.json`.
    - The pod was Ready, so readiness reported a healthy server with unrestored panes.
    - After the directory was restored and the pod restarted, Claude resumed (M).
  - **Renamed while running** (G2a): shells follow the rename, and the shutdown save records the new path. Claude
    then resumed in the new path and blocked at the folder-trust dialog. Moving the directory back and restarting
    recovered it (M).
  - **Implication:** a workspace PVC that fails to mount does not corrupt state. Moving repositories under a live
    Herdr changes the paths that transcripts and trust are keyed by.
  - → REQ-004, REQ-006, REQ-010.
- **FIND-022 — Claude Code writes runtime-fetched content to the home PVC.** [observed]
  - **What:** Claude 2.1.311 cloned the official plugin catalogue (19 MB) into `~/.claude/plugins/marketplaces/`, even
    with `DISABLE_AUTOUPDATER` and related variables set and no plugins installed.
  - **Credentials:** none were written to the PVC, because the token is supplied by environment.
  - **Impact:** small, but it is mutable content outside the immutable image, and an outbound fetch from the pod.
  - → REQ-002 / ADR-0001 §2; egress policy (not yet in scope).

**Surprises:** the whole-pod OOM blast radius (FIND-018). Force delete creates the replacement before the old process
exits (FIND-019). `reload-config` is needed even though the file updates itself (FIND-020). Polling latency varied 30×
(FIND-016). Readiness stayed green with panes in `restore_error` (FIND-021).

## 7. Architecture implications (proposals for review)

These are proposals. No accepted ADR is changed.

1. **Adopt the tested pod shape as the MVP baseline:**
   - Single-replica StatefulSet with separate home and workspace RWO PVCs.
   - `HERDR_CONFIG_PATH` on a ConfigMap, tmpfs state, PSA `restricted`, no ServiceAccount token.
   - An entrypoint that seeds agent config, reconciles hooks and execs `herdr server` with an allowlisted environment.

   Keep the 60 s grace period. It is ample, and costs nothing when shutdown is fast.
2. **Hook lifecycle: reconcile on every start** (FIND-017). Record this decision in an ADR or the architecture doc
   after review.
3. **Recovery verification:** keep readiness as `herdr status server`. Add a post-start check outside readiness that
   reports panes in `restore_error` and expected agents missing (FIND-021). That could be an alert or a status
   exporter, not a probe that restarts the pod.
4. **Config changes:** either run `herdr server reload-config` when the mounted file changes (a small watcher in the
   pod), or switch to a hash-suffixed ConfigMap so each change rolls the pod deliberately (FIND-020). The first avoids
   interrupting agents.
5. **Single writer:** document "do not force-delete herdr-0", and consider an entrypoint guard (for example a lease
   or lock file with the previous pod's identity) for the same-node overlap (FIND-019).
6. **Resource isolation:** FIND-018 is evidence for moving heavy agent work out of the Herdr container (REQ-009 and
   REQ-011, EXP-006). Until then, consider per-pane `ulimit`/`prlimit` or cgroup v2 sub-cgroups if Herdr supports
   them [inference].
7. **GitOps latency:** add an Argo CD webhook for the GitOps repository. Accept that a signed-commit policy makes each
   change an interactive owner action (FIND-016).
8. **Image hygiene:** decide whether Claude's runtime plugin-catalogue fetch is acceptable, or disable or redirect it
   (FIND-022).

Candidate requirement wording for review. REQ-006 could add: "Graceful pod replacement (including GitOps image change
and node relocation) restores layout, cwds and agent conversations automatically. Forced termination loses at most
the last ~5 s of layout changes. A missing workspace directory leaves affected panes recoverable, not re-rooted."
