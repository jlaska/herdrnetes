## Deviations, limits and harness observations

- **Export invocation (operator error, failed closed):** the first `export.sh` call used a relative destination. `export.sh` copies from inside the evidence directory, so every copy failed. Its EXIT trap then removed the destination ("did not complete a passing scan") and nothing unscanned remained. The second call, with an absolute destination, exported 159 files and the scan passed. The lead's derived `obs/run-proxy-decisions-summary.txt` was added afterwards and scanned separately (clean). Harness unchanged; documenting "absolute DEST" is a nit for the owner.
- **The H4 gate can match API-error entries (harness weakness, not triggered).** The `_tr_probe` H4 check greps for any transcript entry of type assistant, and Claude Code also writes API errors as entries of that type. Here every assistant entry was a real model response (independent Sonnet review), and the later C0 gates (6 first attempts, the ACK reply) could not have passed on errors alone. A future harness should require usage, a real model id and no `isApiErrorMessage`. This is a proposal, not changed.
- **The supervisor-token-expiry guard was vacuous:** no `openshell.ai/supervisor-token-expires-at` annotation existed on the sandbox pods (the gateway log records a sandbox JWT TTL of 3600 s). Whether the supervisor token would have expired inside a longer outage was not measured.
- **The client tree had 3 PIDs, not the 4 process kinds the README expected.** Zero survivors were verified either way.
- **Scope limits:**
  - n = 1, with about 8.7 minutes of agent life and 24 of 120 steps.
  - One model: Haiku 5.5, effort medium.
  - A **graceful** gateway scale-down only: not a crash, a SIGKILL, an upgrade or a supervisor-pod or node loss.
  - The gateway kept its data PVC.
  - The terminal client was the harness's stand-in, `openshell sandbox connect` in a local tmux server, not a Herdr pane. Coherence was judged by a minimal screen rule (at least 2 input-box rule lines, no escape fragments) on `capture-pane` output.
  - An echoed probe token shows that the model read and answered the input in the same session. It does not show recall of earlier context.
  - Default per-sandbox PVC.
  - The live request headers were not captured. That the placeholder travelled only in the permitted `x-api-key` placement is inferred from OpenShell accepting every request under its single-placement rule (S) and from the loopback header-capture test (O, local).
  - The probe asked for the last completed step but not the codeword, so codeword recall across C1 and C2 was not tested (`codeword=false` is "not requested", not "forgotten").

## Architectural implications (proposal; ADR-0001 unchanged; REQ-009/REQ-011 stay Future)

- For the tested configuration, OpenShell owns the agent's execution lifecycle independently of the terminal client and of a graceful gateway outage of about 2 minutes. A Herdr pane can therefore act as a disposable `sandbox connect` client for a real Claude Code agent: closing or killing it, or briefly stopping the gateway, did not stop the work or break the conversation.
- The model credential path runs in the per-sandbox supervisor, not the gateway, so a gateway outage does not stop model access (O, at this scope). Gateway availability is expected to affect attach and control (I: no attach was attempted during the outage), not the agent's progress. The longer-outage and supervisor-restart cases are untested.
- Credential placement is strict and fails closed. Agent launch configuration must match the profile's single placement (FIND-092/093/095). Any future agent or provider profile needs its own placement check, such as the header-capture test, before a live run.
- This is evidence toward REQ-009 (agent processes surviving client and gateway restarts with an independently managed lifecycle) and REQ-011 (OpenShell isolation). It does not establish either, because upgrades, crash restarts, node maintenance and workload-pod loss are untested.

## Recommendation on Stage C4

**Evidence now supports preparing a C4 proposal, not running it.**
- C0–C3 passed on every axis, so the precondition the earlier recommendation named is met. The open question is what happens when the agent's own workload pod is lost: native session resume from persisted state, classified as resume, not continuity.
- C4 needs separate owner decisions that this run did not touch: a durable or externally owned PVC, possibly `allow_driver_config`, and Git or the ledger for repository checks (D1).
- Before or alongside C4, the owner may want cheaper continuity checks that reuse this harness unchanged, each needing its own approval:
  - a repeat C0–C3 for n > 1;
  - a gateway **pod delete or short-grace termination** variant of C2, which Stage B covered only for a synthetic process.

The agent does not start any of these.
