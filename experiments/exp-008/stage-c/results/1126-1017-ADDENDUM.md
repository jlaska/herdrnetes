## 1. Proposed narrowed wording (for the owner's decision)

| Finding | Recorded text, in short | Proposed scope wording | Why |
|---|---|---|---|
| FIND-095 | The corrected launcher's model traffic passed the credential proxy; "only placeholder forms were seen in the readable workload environments and files" | In one live run, the corrected credential integration worked: 26/26 `POST /v1/messages` allowed, 0 placement or request-body refusals. **No real-key-shaped value** was detected in the 5 readable process environments or under `/sandbox`. The placeholder was observed in the agent's **environment**; no file held it (`fs_placeholder_files=0`). It does **not** claim exhaustive absence of secrets (one environment was unreadable) or captured live headers | `obs/c0-X4.txt` counts files with a placeholder as 0, so "placeholder forms in files" overstates it |
| FIND-096 | SIGKILL of the only client did not interrupt the agent; 6 qualifying detached steps; same-session reattach | Client termination did not interrupt the process. There were **6 qualifying detached steps** in the 124 s window, and the reattach was the same-session writer with the prefix intact. **There is no strong proof of contextual recall**: the C3a reply did not name the last step, and the codeword was not asked for | `metrics/c1-reattach-probe.json` `reply_mentions_last_done=false` |
| FIND-097 | A graceful gateway outage did not interrupt the agent; 5 qualifying steps while the gateway was down; "the supervisor allowed five `POST /v1/messages` during the gateway-down window" | The graceful gateway outage (scale 0 → 90 s → 1) did not interrupt the process. There were **5 qualifying steps** while the gateway was absent or not Ready, and the reattach was the same-session writer. The **five HTTP requests during the outage are supported by local supervisor evidence**, not by independently reproducible public raw logs. The exported window metric counts transcript `api-request` entries (`metrics/c2-gwdown-window.json` `api_requests_in_window=5`) | The supervisor log is local only (`raw/`); the exported proxy summary has no per-event timestamps |
